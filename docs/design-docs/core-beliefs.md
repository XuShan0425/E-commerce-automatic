# 智能体优先的操作原则

> 这是我们的核心理念文档。每条原则都是团队讨论和实践中沉淀出的约定。
> 智能体应将这些原则作为设计决策的第一参考。

## 1. Human steers. Agents execute. The repository is the source of truth.

人类掌舵 — 设定目标、定义约束、验证结果。
智能体执行 — 编写代码、运行测试、打开 PR。
代码仓库是唯一的真相来源 — 不存在于仓库中的知识视为不存在。

**Why**: 这是 OpenAI opencode 团队验证过的最高杠杆工作模式。人类的时间和注意力是唯一真正稀缺的资源。

**How to apply**: 每次发现智能体缺少信息时，不是口头告诉它，而是将信息编码到仓库中（文档、lint 规则、测试）。

## 2. 渐进式披露，而非一次性倾倒

智能体从 AGENTS.md (~100行) 开始，按需导航到更深的文档。不要把所有规则塞进一个文件。

**Why**: 上下文窗口有限。当所有信息都"重要"时，智能体进行本地模式匹配而非有意识导航。

**How to apply**: AGENTS.md 是地图，docs/ 下的专题文档是目的地。每个文档有清晰的边界和进入条件。

## 3. 将品味编码为机械规则

人类的代码风格偏好如果不编码为自动化检查，就会持续被违反。

**Why**: 人类审查的带宽有限，无法在每个 PR 中重复相同的风格反馈。

**How to apply**: 发现一个模式问题 → 写一个 lint 规则 → 错误信息写成给智能体的修复指令。见 `scripts/lints/`。

## 4. 文档垃圾回收

文档如果不持续维护，会变成陈旧规则的坟场。需要机械化的"花园整理"。

**Why**: 信息腐烂比没有信息更危险 — 智能体会基于错误的假设做决策。

**How to apply**: 每周自动运行 `doc-gardening.py`，检测过时引用并发起修复 PR。

## 5. 在边界处验证一切

所有外部数据（用户输入、API 响应、AI 输出、HTML 抓取）必须在系统边界处验证。

**Why**: 速卖通页面结构会变化、AI 可能返回非 JSON、用户可能输入错误格式。边界验证将脏数据隔离在系统外围。

**How to apply**: Pydantic schemas in api/, 类型转换 in services/api_interceptor.py, JSON 解析 + schema 验证 in decision_engine.py。

## 6. 偏向"枯燥"的技术

对智能体来说，API 稳定、训练数据丰富、模式可预测的技术比"现代"但小众的技术更容易正确使用。

**Why**: 智能体基于训练数据中的模式工作。FastAPI + SQLAlchemy + Playwright 的组合在训练数据中大量存在，智能体更可能生成正确的代码。

**How to apply**: 选择依赖时优先考虑：API 稳定性 > 社区规模 > 训练数据覆盖度 > 功能丰富度。

## 7. 纠错成本低，等待成本高

在智能体吞吐量远超人类注意力的系统中，快速合并 + 后续修复优于长时间的门控审查。

**Why**: 智能体每小时可以处理多个 PR。阻止一个 PR 等待"完美的"审查意味着失去了智能体在等待期间可以完成的其他工作。

**How to apply**: PR 生命周期短。偶发测试失败通过重试解决。但绝不跳过安全底线（人工审查、不自动合并）。

## 8. 架构约束 > 微观管理

强制执行不变量（依赖方向、层级边界），而非规定具体实现（用哪个库、怎么写循环）。

**Why**: 智能体在严格边界和可预测结构中最有效。微观管理实现细节反而降低产出质量。

**How to apply**: `scripts/lints/check-architecture.py` 检查 import 方向。不用规定智能体必须用哪个 HTTP 客户端。
